# 多语言（zh-CN / en-US）

- **Date**: 2026-11-19
- **Status**: done
- **相关**: `docs/todo.md` 第 4 项、`frontend/locales/`、`crates/app/src/i18n.rs`、
  `scripts/check-i18n.js`

## 事实

- 设置项 `language`: `auto`（默认）/ `zh-CN` / `en-US`。`auto` 在启动与切换设置时解析一次：
  先看 `LC_ALL`/`LC_MESSAGES`/`LANG`，Windows 上再问 `GetUserDefaultUILanguage`，
  非中文回退 `en-US`。运行中改系统语言需要重启 efto。
- **词典只有一份**：`frontend/locales/<tag>.json`（扁平 key，`区域.组件.动作`）。
  前端 `i18n.js` 用 `fetch` 加载；Rust `crates/app/src/i18n.rs` 用 `include_str!` 嵌入同一份文件，
  托盘/窗口标题与页面不会出现两套翻译。缺失 key 回退中文并 `tracing::warn!`，不回显 key。
- 前端约定：`data-i18n`（textContent）、`data-i18n-html`（innerHTML，仅用于带 `<code>`/`<kbd>` 的文案）、
  `data-i18n-placeholder/-title/-aria-label`；脚本里用 `window.eftoI18n.t/tf`。
  页面中文先作为 HTML 兜底，词典就绪后覆盖。
- 语言变更：`set_settings` 检测 `language` 变化后重建托盘菜单（菜单文本不能原地改）、
  同步设置/剪贴板/帮助窗口的原生标题，并 `emit("settings:language")`；
  主窗口收到后 `location.reload()`，设置窗口保存后自行重载。
- 插件不扩清单字段：宿主 `efto.locale` 跟随解析后的语言（`commands.rs` 的 PluginContext 与
  CLI 宿主都改为读 `settings.language`），插件自己决定文案。

## 判据

- 新增用户可见文案必须进两份词典；`scripts/check-i18n.js` 接进 `verify.ps1`，
  校验 key/占位符一致、HTML/JS 引用的 key 存在、HTML 残留中文报行号（语言名白名单）。
- 词典放 `frontend/` 而不是仓库根 `locales/`：`frontendDist` 只打包该目录，
  放外面运行期 `fetch` 不到。
- 帮助文档按 `auto` 解析结果选 `.zh-CN.md` / `.en-US.md`，不再有单一 `help.md`。

## 验证

- `crates/app/src/i18n.rs` 3 个测试：两份词典 key 集合一致、托盘/窗口标题 key 存在、
  缺失 key 原样返回。
- `node scripts/check-i18n.js`：281 keys × 2 语言全部对齐，HTML/JS 引用全部命中。
- 未验证：英文在 520px 搜索框内的实际排版、托盘重建的视觉切换、插件读取 `efto.locale`
  后的文案切换；见 `docs/verification.md`。
