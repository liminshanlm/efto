# macOS 支持 Phase 0/1：工程基座 + core 平台层 + CLI 主链路

- **Date**: 2026-11-21
- **Status**: done
- **相关**: `docs/macos-support-plan.md`、`docs/verification.md`、`scripts/{bootstrap,cargo,dev-run,verify}.sh`、
  `.github/workflows/ci.yml`、`crates/core/src/apps/appbundle.rs`、`docs/roadmap.md`

## 现象

仓库整体是 Windows 起家：`.lnk`/注册表/开始菜单发现、PowerShell 命令源、Win32 系统集成、
`scripts/*.ps1` 工具链、`vendor/` 只有 Windows 的 rusty_v8 静态库。mac 上不仅跑不起来，
连编译都不过（`ureq` 被误放进 `[target.'cfg(windows)'.dependencies]`、`open_with` 无非
Windows 实现）。计划见 `docs/macos-support-plan.md`（v1 = 唤起 → 搜索 → 启动应用/跑插件
+ CLI 主链路；系统集成类推迟）。

## 做法

- **工程基座（Phase 0）**：`scripts/bootstrap.sh` / `cargo.sh` / `dev-run.sh` / `verify.sh`
  镜像 Windows 四件套（`.ps1` 保持纯 ASCII 不动）；rusty_v8 补
  `librusty_v8_release_aarch64-apple-darwin.a.gz` 进 `vendor/`（sha256 钉在 `cargo.sh`，
  `.cargo/config.toml` 的 `[env]` 无法按 target 区分，mac 靠 wrapper 覆盖这两个变量）。
  `check-time-probe.js` 的 exe 名按平台取 `efto` / `efto.exe`（原来写死 `.exe`，ENOENT
  被吞成"0 行"导致全量 FAIL）。
- **应用发现（Phase 1）**：新增 `apps/appbundle.rs`（扫 `/Applications`、
  `~/Applications`、`/System/Applications` 的 `*.app`，Info.plist 取名 + bundle id 进别名；
  `.app` 是叶子不递归进 `Contents/MacOS`）。`AppSource::AppBundle` 先验 1.00 与开始菜单同级，
  `TargetKind::AppBundle` 由 launch 走 `open`（args 经 `--args` 透传）。scanner 在 mac 捡
  裸可执行文件（可执行位判定、跳过 `.app` 子树）；`system_tools` 白名单只在 Windows 编译
  （ms-settings: 这类 URI 漏进 mac 索引就是打不开的结果）。
- **命令源**：`CommandShell` 加 `zsh` / `bash` / `fish`，平台默认（Windows PowerShell /
  mac zsh），`Settings::normalize_for_platform` 把跨平台配置回落（旧 shell 的显式路径一并
  清掉，防止被当成新 shell 的启动路径）；POSIX shell 走 `-lc`。`run_command_terminal`
  在非 Windows 明确报错（终端模式要接 Terminal.app，是 v1.5，不能静默把输出跑丢）。
- **搜索源切分**：`win_settings` / `everything` 模块只在 Windows 编译；`BuiltinAction`
  按 `supported_on_platform` 过滤——截图/平铺/快捷键指南/通用动作/文件缓冲在 mac 不进
  搜索结果。`KNOWN_TOOLS` 平台子集（mac：clipboard / lock_screen / snippets），
  `lock_screen` 用 `pmset displaysleepnow` 真做了。
- **CI 矩阵**：`.github/workflows/ci.yml`（windows-latest + macos-latest，各跑
  bootstrap + test + verify）。仓库在 Codeup 上，云效流水线照同一组命令配置两个任务。

## 判据

- mac 上 `cargo test --workspace` 全绿：efto-app 104 / efto-core 222 / efto-jsrt 48（真起 V8）。
- `scripts/verify.sh` 全绿（ALL CHECKS PASSED）：index / plugins / 拼音（fy→翻译）/
  计算器不劫持 / hello-js / timestamp-ts 双向 / translate 空载荷 / 未知插件报错 /
  run-command dry-run+echo / capabilities / files --dry-run / focus not-found /
  launch dry-run + 真启 TextEdit 再 quit。
- 反例测试（硬性约定 2）：bundle 内 helper 不被登记、忽略规则整包吃掉、mac 上
  `ms-settings:` 不出设置页、系统工具白名单必须为空、平台不支持的动作不进搜索结果。
- 明确报错（硬性约定 3）：系统动作（睡眠/重启/注销/清空回收站/屏保）、`打开方式`、
  终端模式执行，在非 Windows 上都返回"当前平台不支持：…"而不是静默成功。

## 没验证 / 留给后续

- **Windows 侧未在本机回归**：改动理论上不碰 Windows 行为（AppBundle 在 Windows 不出现、
  CommandShell 默认仍 Powershell、KNOWN_TOOLS Windows 列表原样），但要等 CI 矩阵或
  Windows 机器跑一次 `verify.ps1` + `test --workspace` 才算闭环。
- hosts 能力（读 /etc/hosts 可用、save 无提权路径）未按计划收口，Phase 2 随
  `platforms` 清单字段一起做。
- GUI（热键/托盘/图标/插件窗口）是 Phase 2；tile/截图/通用动作等是 Phase 4。
