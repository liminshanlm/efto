# 双屏截图只能截一个屏幕：跨屏覆盖层窗口只在一块屏上渲染

- **Date**: 2026-11-21
- **Status**: done
- **相关**: `crates/app/src/{windows,commands}.rs`、`frontend/screenshot.js`

## 现象

双显示器下截图"只能截一个屏幕"。捕获层早已验证两屏都在图里，但实际使用时
一块屏能看到截图覆盖层（压暗+提示条），另一块屏完全是活的桌面，点不了选不了。

## 根因（逐层取证）

1. **覆盖层单窗口跨两块屏时，WKWebView 只在其中一块屏上渲染**——CGWindowList
   实测窗口 frame 确实是 (0,0,3360,1080) 覆盖两屏、窗口 level 也是置顶，
   但像素级对比（同一屏开/关覆盖层的截图平均亮度）证明另一块屏**毫无渲染痕迹**
   （亮度比 1.004）。屏上看起来"活着"的其实是冻结背景和活桌面同形，极易误判。
2. 另有两个伴生缺陷一并修掉：
   - tao 把窗口 y 按菜单栏下推 25 点，而前端按"窗口原点=图原点"换算选区 → 纵向偏 50px；
   - `always_on_top` 浮动级压不住同级置顶窗口（实测被普通窗口盖过）。

## 做法

- **mac 改为每屏一个覆盖层窗口**（`screenshot-0..n`，各自铺满本屏）——单屏内渲染
  没有跨屏坑；窗口几何用 Logical（= 点）。
- **映射自愈**：`screenshot_begin` 回传窗口在图内的 `off_x/off_y/view_w/view_h`
  （图坐标 = 点 × 主屏 scale，与窗口本屏 scale 的换算在 Rust 侧做，混合缩放下
  两者不同源），前端按切片对齐背景与选区坐标——窗口被菜单栏推移/摆放偏移都能吸收。
- 覆盖层 `setLevel(NSScreenSaverWindowLevel=1000)` 保证压住普通窗口；
  长截图只保留发起窗口，其余屏覆盖层关闭。

## 判据

- 诊断钩子（EFTO_DEBUG_SHOT，验后已删）实测：每屏窗口尺寸/位置精确
  （screenshot-0 = 1440×900@0,0；screenshot-1 = 1920×1080@1440,0）；
  **两屏截图均出现压暗+提示条**（此前 d1 平均亮度 109 → 83，45% 压暗生效）。
- 全量测试 145/241/48 绿；verify.sh ALL CHECKS PASSED。

## 教训

- "窗口在不在那儿"（frame/level 读数）不等于"画面渲染到那儿"——**混合多屏下
  要像素级验证**（开/关对比 + 平均亮度），冻结背景与活桌面同形时肉眼会骗人。
- 跨屏单一 WebView 窗口是雷区；每屏一窗 + 映射自愈是稳妥架构。
