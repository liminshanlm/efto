# 双屏截图一屏整体下沉：位图上下文左下原点当左上用

- **Date**: 2026-11-22
- **Status**: done
- **相关**: docs/verification.md「双屏截图"一屏内容整体下移"」、crates/app/src/screenshot.rs

## 现象

用户报「有一屏内容位置向下偏移」。覆盖层窗口几何、层级、尺寸读回全都正常，
所以前两轮都在窗口摆放上打转。

## 根因

`crate::screenshot::capture_region`（mac）把每块屏的 `CGDisplayCreateImage` 画进
"点矩形 × 主屏 scale"槽位时，用的是全局**左上**原点 y；但 `CGBitmapContextCreate`
出来的上下文是**左下**原点。于是每块屏的图实际落在"距画布底边该高度"的位置：

- 画布高 = 最高那块屏（1080 点）
- 主屏 900 点 → 下沉 1080 − 900 = **180 点**，顶部留 180 点空槽
- 副屏正好 1080 点 → 位移 0，所以"只有一屏"偏移

空槽区域在强制 alpha=255 后是纯黑，正是用户截图里那条黑带。

## 判据（可复用的实证手法）

覆盖层在屏时 `screencapture -x -D n` 各拍一张，撤掉覆盖层再拍一张实时桌面，
对两图做边缘图 + 纵向互相关取最佳位移：

- 修复前：display1 = +180 点、display2 = 0
- 修复后：两屏都 0

**不要**用窗口 frame / tao readback 判断"有没有偏移"——它们本轮全是正常值。

## 修复与加固

1. 合成矩形 y = `画布高 − 左上 y − 该屏高`（唯一真 bug）。
2. 覆盖层几何确定性下发：建窗后直接 `setLevel:` + `setFrame:display:`，
   映射按 `displays()` 查表，不再读 tao 的位置/scale（1x 屏上 scale 会报成 2.0）。
3. 截图前轮询等主窗口真的不可见（≤400ms）再捕获，替掉固定 sleep 140ms。
