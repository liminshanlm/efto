# 截图捕获上下颠倒 + 多屏映射漂移

- **Date**: 2026-11-21
- **Status**: done
- **相关**: `crates/app/src/screenshot.rs`（mac 捕获层）

## 现象

用户报"只截取了一个屏幕，不能截另一个屏幕"。把捕获 dump 成 PNG 直视后发现：
两块屏的内容**都在**，但整图**上下颠倒**（文字镜像），且混合缩放多屏（主屏 2x +
副屏 1x）下单次 `CGWindowListCreateImage` 的光栅化与统一坐标系不吻合——
选区映射会漂到别的屏，"在屏 2 上框选却截出屏 1 的内容"即此症状。

## 根因

1. **翻转写反**：位图上下文的缓冲行序本来就是自顶向下，我却按"原点在左下"
   又做了 TranslateCTM+ScaleCTM 翻转，结果整个颠倒（dump 实证）。
2. **单次全包围盒捕获的光栅化口径不可控**：CGWindowListCreateImage 对混合缩放的
   多屏矩形不保证按"点 × 主屏 scale"均匀光栅化，映射关系因此漂移。

## 做法

- 去掉翻转（直接画）。
- 改**逐屏原生捕获再合成**：`CGDisplayCreateImage(id)` 拿每块屏的原生像素，
  画进"该屏点矩形 × 主屏 scale"的槽位（上下文自动裁剪，区域捕获共用同一核心）。
  混合缩放多屏下映射精确：鼠标在屏 2 的点坐标 ×scale 与画布槽位一一对应。

## 判据

- dump 整屏 PNG 目视：方向正确、两屏内容与物理布局一致（左 iTerm2 @2x +
  右桌面 @1x 并排）。
- 单测 145/241/48 全绿（真机捕获测试含区域 64×48 尺寸精确断言）；verify.sh 全绿。

## 教训

位图上下文方向**以实证为准**（dump 成图看一眼，别背文档）；跨缩放多屏不要赌
单次捕获 API 的光栅化口径，逐屏取原生像素自己合成才是精确映射。
