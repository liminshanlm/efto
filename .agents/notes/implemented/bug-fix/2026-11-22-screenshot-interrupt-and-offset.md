# 截图会话被"弹出搜索框 + 内容下移"打断：单实例转发 show_main + 窗口落位漂移

- **Date**: 2026-11-22
- **Status**: done
- **相关**: `crates/app/src/{windows,commands}.rs`、`frontend/screenshot.js`

## 现象

双屏截图时：点击截图瞬间一切正常（搜索框隐藏、内容不偏移），**一会后内容向下偏移
且搜索框又出现了**。

## 根因（两个现象同一来源）

用户机器上 `/Applications/efto.app` 长期在跑；**任何第二个 efto 实例启动都会经
单实例插件转发 `show_main`**（开发调试、重复点开 .app、诊断脚本都算），于是：

1. **搜索框被直接拉起来**——截图会话中也不例外；
2. `show_main` 触发焦点/窗口约束重算，**覆盖层窗口被菜单栏约束从 y=0 挪到 y=25**，
   背景图跟着窗口下移 25pt →"内容向下偏移"。两个症状同时"一会后"出现正是同一次
  转发所致（时间上撞上排查过程中的诊断实例启动，表现得像自发）。

另有一个伴生弱点：`screenshot_begin` 在页面加载时读窗口位置，而窗口落位是异步的
（tao 的 async setFrame + 约束重算），读早了映射就错。

## 做法

- **截图会话守卫**：`show_main` / `show_main_quiet` 在任何截图覆盖层打开期间直接
  忽略显示请求（来源无关地兜住：单实例转发、插件输出、托盘）。
- **映射自愈**：新增轻量 `screenshot_offset` 命令；前端在窗口落位后（300/800/1500ms）
  轮询刷新偏移，并在提交/长图启动前强制取最新偏移再算坐标——窗口被挪到哪都对得上。

## 判据

- 全量测试 145/241/48 绿；verify.sh ALL CHECKS PASSED；新包已重打。
- 复现条件（原）：截图会话中启动第二个 efto 实例即弹搜索框；修复后 show_main 被
  守卫忽略（日志记"截图会话进行中，忽略主窗口显示请求"）。
- 人工复验：截图过程中故意再开一个 efto 实例，搜索框不应出现、内容不应偏移。

## 教训

多实例应用的"单实例转发"是全局副作用源；**模态会话（截图/录制）期间必须抑制
这类被动 UI 唤起**。窗口摆放是异步且会被系统再约束的，映射类读数要么落位后再取、
要么提交前重取。
